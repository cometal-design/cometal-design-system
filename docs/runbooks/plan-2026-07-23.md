# План настройки Cometal Design System — 23 июля 2026

## Результат дня

К концу дня пять источников истины работают в одном контуре:

1. Figma DS Core — визуальная модель.
2. Git specifications/registry — спецификации, ID и статусы.
3. Git tokens/React — токены и исполняемая библиотека.
4. Storybook — опубликованная документация и проверки.
5. Obsidian — открытая и проверенная база знаний.

GitHub размещает оба Git-источника, Vercel публикует Storybook. Они являются инфраструктурой, а не шестым и седьмым источником.

## Что подготовить до начала

От пользователя потребуется:

- доступ к рабочему email;
- телефон или authenticator для 2FA;
- доступ к существующему GitHub, если аккаунт есть;
- доступ к существующему Vercel, если аккаунт есть;
- возможность подтверждать OAuth, CAPTCHA и письма;
- решение по платному тарифу Vercel только если нужен встроенный общий пароль;
- 30–60 минут присутствия у компьютера во время входов и подтверждений.

Не требуются:

- доступ к репозиториям разработчиков;
- участие команды разработки;
- Obsidian Sync;
- корпоративный домен на первом запуске;
- публикация React-пакета в npm.

## Разделение работы

**Codex выполняет:** установку инструментов, команды Git, настройку repository, подготовку Vercel build, проверку Vault, тестовый релиз и обновление документации.

**Пользователь выполняет:** ввод email и паролей, 2FA, CAPTCHA, OAuth-подтверждения, платёжные решения и финальное подтверждение имён аккаунтов/организаций.

Codex не просит присылать пароль в чат и не записывает его в файлы.

## 11:00–12:30 — GitHub

### Решение по аккаунту

- Если личный GitHub уже есть — используем его как временного индивидуального владельца.
- Если аккаунта нет — создаём индивидуальный аккаунт на рабочий email.
- Общий административный логин не создаём: действия должны иметь конкретного владельца.

### Настройка

1. Установить GitHub CLI `gh`.
2. Авторизоваться через browser/OAuth.
3. Включить 2FA и сохранить recovery codes в Apple Passwords.
4. Создать GitHub Organization. Рабочее имя: `cometal-design`; если занято — выбрать нейтральный вариант вместе.
5. Создать private repository `cometal-design-system` без README и starter-файлов.
6. Подключить его как `origin` к локальному репозиторию.
7. Push ветки `main` и проверить три существующих коммита.
8. Добавить описание репозитория и ссылку на документацию.
9. Настроить защиту `main`: запретить force push и deletion; требовать pull request перед merge, если тариф это позволяет.
10. Включить доступ Vercel GitHub App только к этому repository.

**Готово, если:** новый компьютер теоретически может клонировать repo, а `git status` локально чистый и `main` совпадает с GitHub.

## 12:30–13:30 — Vercel

### Решение по аккаунту

- Если Vercel уже есть — используем существующий индивидуальный аккаунт.
- Если аккаунта нет — создаём его через GitHub OAuth.
- Project создаём с нейтральным именем `cometal-design-system`.
- При появлении компании Project переносится в корпоративную Vercel Team.

### Настройка проекта

1. Импортировать GitHub repository.
2. Framework Preset: `Other`.
3. Root Directory: корень repository.
4. Node.js: версия из `package.json`, сейчас `>=22`.
5. Install Command: `pnpm install --frozen-lockfile`.
6. Build Command: `pnpm build:storybook`.
7. Output Directory: `apps/storybook/storybook-static`.
8. Production Branch: `main`.
9. Запустить первый Production deployment.
10. Проверить главную страницу и все семь Foundation stories.
11. Записать Production URL в `registry/sources.json`, Obsidian и README.

**Готово, если:** Storybook открывается по постоянной Vercel-ссылке, а deployment связан с commit SHA.

## 13:30–14:00 — Защита Storybook

1. Проверить тариф Vercel.
2. Если доступен Password Protection — задать отдельный viewer password и сохранить его только в Apple Passwords.
3. Если функция недоступна — не покупать тариф автоматически. Зафиксировать решение:
   - временно оставить URL доступным по ссылке;
   - или следующим этапом добавить собственный слой авторизации;
   - или перейти на тариф, поддерживающий Password Protection.
4. Открыть deployment в приватном окне и проверить фактическое ограничение доступа.

**Готово, если:** режим доступа известен, протестирован и записан в реестре; нет ложного ощущения приватности.
